# The library owns the Tick loop

ticknet runs the fixed-rate Tick loop itself and calls the game once per Tick with the Tick number; everything the game sends during a Tick is flushed together when the Tick ends, in as few Datagrams as possible (one `sendMany` call on UDP), and the Client batches its own sends at a fixed send rate. The alternative was a passive library that sends on every call and lets the game run its own loop. We chose to own the loop because batching per Tick is what keeps Datagram counts and per-Datagram overhead low, because acknowledgements, resends, keepalives and the per-Tick Send budget all need a regular heartbeat, and because a shared Tick number gives Server and Client a common timestamp. The cost is that a game cannot send a Message out of band between Ticks.
